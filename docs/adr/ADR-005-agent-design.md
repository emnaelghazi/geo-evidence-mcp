# ADR-005: Agent design

- Status: Accepted
- Date: 2026-11-14

## Decision

A LangGraph state machine: `intake -> plan -> select_data -> analyze -> check_evidence -> narrate ->
validate -> finalize`, with refusals routed straight to `finalize`.

- **The model does two things only**: turn the question into a structured `Plan` (forced tool call,
  validated by Pydantic) and write the final sentences from a JSON evidence packet.
- **Everything between is code**: place resolution, scene choice (least cloudy first, 20% then 60%
  with a caveat), calls to the MCP tools (in-process FastMCP client, so the agent uses the same
  surface external hosts use), evidence checks.
- **`check_evidence`** refuses to answer unless every block is in the store and its `args_hash`
  matches its recorded request.
- **`validate`** runs the claim validator (ADR-004) on the draft. A rejected draft is regenerated
  with the offending numbers named, up to three narrations. If it still fails, the answer is built
  by code from the tool outputs (`answered_from_template`), so an unsupported number never reaches
  the user. Caveats (seasonal gap, cloud, clipping, negative reflectance) are generated by code and
  appended outside the model's text.
- **Models are behind a protocol** (`AgentModel`): `AnthropicModel` for real runs, `ScriptedModel`
  for deterministic tests of every path.
- **Tracing is behind a protocol** (`Tracer`): `RecordingTracer` (tests), `LangfuseTracer`, no-op.
  Every node, tool call and model call is a span. Tool spans store the exact arguments, so
  `compute_args_hash(span.name, span.input)` equals the block's `args_hash`: a run is reconstructible
  from its trace alone (tested). `run_id` is passed to every tool call and stored in the block's trace.

## Deliberately not done yet

- **Geocoding.** Places come from a tiny gazetteer (`aoi.GAZETTEER`) or user-supplied coordinates.
  An unknown place is refused with the list of known ones. A geocoder (Nominatim / GeoBoundaries) is a
  later, separate decision because it adds a network dependency and ambiguity handling.
- **Rich refusals and trap handling** are M5. M4 refuses: unsupported plans, unknown places, empty
  or oversized questions, periods without scenes, unverifiable evidence.
- **Scene choice is simple**: one least-cloudy scene per period, no compositing. Cloud masking via SCL
  is M5.

## Known limits

- The validator checks that numbers come from tools, not that the sentence is true; two scenes from
  different seasons will happily produce a (caveated) change number.
- The `AnthropicModel` request shape is tested against the real SDK with a mocked transport, not
  against the live API until `RUN_INTEGRATION=1` is run with a key.
- The Langfuse adapter is tested with a local OpenTelemetry exporter, not against a Langfuse server.
